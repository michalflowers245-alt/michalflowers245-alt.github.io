01

项目与问题

阅读之后，资料怎样再次被使用

AI Web Clipper／快摘面向持续收集网页资料的学生、研究者和内容创作者。2026 年 4—5 月，我作为产品负责人参与需求研究、工作流与模块设计，并组织体验测试。

截图、复制、手动补链接再交给 AI 的过程中，标题层级、代码、公式线索与来源容易丢失。快摘要解决的是资料保存以后，能否再次找到、核对和加工。

02

本人角色

我的工作从需求到体验验证

我将用户任务拆成阅读、摘录、清洗、保存、整理与导出，确定功能优先级；通过线下体验收集反馈，将用户需求与真实网页样本中的抽取问题一起带回迭代。技术实现与页面开发通过协作推进。

03

目标与关键判断

关键取舍：先保证保存与导出

需求集中在格式保真、抽取稳定性、账号入口和权限信任。我优先保证“可回看、可追溯、可导出”：即使不调用 AI，也能完成一次资料收集。

最小版本先处理网页文本和可控制的站点样本，暂缓 PDF 标注、所有网站适配和深度知识库集成；AI 总结与改写接在可靠的采集、保存之后。

04

推进流程

从需求材料推进到可检查流程

  1. 整理需求：把“导出乱、内容丢、入口难找”等描述转成具体问题，区分采集、保存与复用环节。
  2. 收敛范围：通过机会卡与产品设计文档明确目标用户、触发方式、必要能力和暂缓事项。
  3. 定义产物：每次采集保留正文和来源元信息，导出的 Markdown 应可读、可编辑。
  4. 验证流程：结合扩展、界面材料与体验反馈，检查从当前网页到资料库、再到导出的路径。

05

核心产品或机制

采集、资料库、专题与导出

一份网页资料的保存路径

  1. 网页输入从当前网页或选中文本采集正文，保留标题层级、图文关系与来源信息。
  2. 归档整理将资料保存到 Library，按专题归档并通过搜索再次找到。
  3. 带走内容通过摘录菜单复制或下载 Markdown，继续编辑和复用资料。

我负责流程设计与体验组织，优先打通采集、保存和可编辑导出。

  • 采集范围：当前页或选中文本；整理可读正文并保留来源元信息。
  • Library：搜索、网页归档与来源；Move to Project 可归入已有专题或创建项目。
  • 两处导出入口：摘录菜单提供保存、复制 Markdown 与下载；Export Draft 展示 Markdown、ZIP 和来源块设置。

06

代表案例与材料

具体案例：代码提取出来就够了吗

《第一次测评深度分析》· 第14—17、28页

原测评里的两种不同失败

原报告将网页与导出的 Markdown 对照。我在产品协作中据此区分“内容没有留下”与“内容留下但结构不可读”，而不是统一归为排版问题。

MDN · 代码内容缺失
正文已有输出，但代码框缺失。第15页原文：“可以看到markdown完全没有将该JS代码框提取出来。”相邻页面保留原网页与导出结果对照。
React · 分行结构丢失
第28页原文：“我们的markdown对代码本身都没有分行，都搞在一起了。”此时问题不是代码有没有被提取，而是读者能否继续使用。
检查标准
正文完整、结构可读、素材关系正确分别检查；页面看起来有内容，不作为抽取成功的唯一判断。

节选来自历史测评，不代表当前版本仍有同样缺陷或已经修复。报告多数结果以 Obsidian 阅读模式展示，不等同原始 Markdown 源码。

除上述代码问题，报告还记录了多标签代码只保留默认内容、图片与图注分离。它们提醒我，正文已经提取并不代表素材关系也被保留；讨论功能优先级时，需要回到具体网页样本。

材料说明历史测评第 14—17 页记录 MDN 代码缺失，第 28 页记录代码分行问题，第 37—41 页记录图注关系与多标签代码。它们是对应版本的问题样本，不代表当前版本仍存在相同缺陷。
